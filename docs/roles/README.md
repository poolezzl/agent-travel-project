# R1-R8 角色开发规范

> 本目录按 `docs/01-需求与整体设计.md` 第五章的 R1-R8 分工拆分。每个负责人只实现本文件所列范围；跨模块变更必须先更新公共契约并经 R1 终审。

## 阅读顺序

1. 所有人先读 [00-公共工程与协作规范.md](00-公共工程与协作规范.md)。
2. 再读本人主责文档；接口依赖方同时阅读对应模块文档和 `agents/` 下的 Schema。
3. 全局顺序以 `docs/04-逐步开发提示词.md` 为准；本目录只定义公共约束和角色实现细则。
4. 技术、产品和质量决策以 `docs/02-开发决策基线.md` 为准；接口以 Schema/OpenAPI 为准。

## 阶段对照

| 阶段 | 并行主线 | 退出条件 |
|---|---|---|
| M0 | R1 契约/架构；R4 网关；R5 骨架/Mock；R7 数据与评估；全员评审 | 契约、供应商、首发城市和开放问题冻结 |
| M1 | R1 总控；R2 路线/天气；R5 账号/API；R6 基础界面 | 单城三日端到端，事实字段零无来源 |
| M2 | R3 三类内容 Agent；R4 修正/版本；R6 对话与 diff；R7 评估 | 七 Agent、降级、局部修改均可用 |
| M3 | R8 榜单/社区/历史/偏好；R5 社区共享基建/导出/提醒/积分；R6 完整体验；R7 质量回归 | 生成→修改→导出→分享闭环 |
| M4 | 全员联调、加固、部署 | 安全、性能、恢复和验收通过 |

所有模块的共同完成定义、事件字段、禁止事项见 `00` 文档；不得复制粘贴为各模块的不同版本。
