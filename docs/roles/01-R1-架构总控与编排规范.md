# 01 R1 架构、总控与编排规范

## 1. 责任边界

R1 主责需求可追溯、架构 ADR、总控 Agent、LangGraph 编排、任务状态机和 Schema/OpenAPI 终审；不实现路线算法、知识库运营、LLM 网关内部策略或前端具体页面。R1 是唯一用户对话链路的裁决者，子 Agent 之间绝不直连通信。

## 2. M0 交付

1. 输出上下文、容器、首次生成、局部修改、数据流、降级 Mermaid 图；冻结 Java↔Python OpenAPI、Agent Schema 版本和错误码目录。
2. 建 ADR：双栈边界、事务 Outbox + Redis Streams、SSE 进度、版本快照、来源元数据、缓存所有权、积分一致性和人工确认。
3. 定义状态机：`CREATED→BALANCE_RESERVED→QUEUED→PARSING→COLLECTING→SCHEDULING→ROUTING→ASSEMBLING→SUCCEEDED/PARTIAL/FAILED`，另含 `AWAITING_CONFIRMATION`、`CANCELLED`、`REFUNDED`。逐一给出允许迁移、操作者、前置条件、超时和恢复规则。
4. 建契约索引和兼容性 CI：Schema Draft-07 校验、样例校验、OpenAPI 破坏性检测、Java/Python 消费者测试。

## 3. 编排要求

- 首次生成固定为：鉴权/报价/预扣→需求解析与可行性预检→资讯/天气/预约并行→日级分配→逐日路线并行→餐住→质量校验→整合→创建不可变版本。硬冲突返回可选项，不得擅自删必去点。
- 调度只传最小必要数据，按依赖 DAG 执行；每个步骤写 `task_step(task_id, step_name, attempt_no, status, input_hash, output_ref)`，以租约/心跳避免重复 Worker 领取。
- 结果合并采用确定性规则：显式用户约束 > 闭馆/预约/开放时间 > 可达与时间窗 > 天气安全 > 预算 > 软偏好。总控的解释文案不得覆盖事实字段。
- 子 Agent 部分失败继续生成但汇总 `degraded_fields`；路线失败先精确缓存，再标识直线估算；无可行行程、非法模型输出、余额/版本冲突进入明确终态。

## 4. 局部修改与恢复

- 修正输入必须含 base_version、用户锁定项和指令。总控只重跑影响范围内 Agent，未受影响快照复用；波及必去点、已确认预约、跨日硬冲突时转确认态。
- Worker 崩溃后从最后一个成功且仍新鲜的步骤恢复；重试同一 task/step 幂等，不能重复版本或扣费。进度事件用单调 `sequence_no`，断线由前端补拉。
- 终态触发一次结算：成功确认预扣，失败退款，部分成功按业务已确认策略；R1 只定义编排触发点，账务由 R5 实现。

## 5. 验收与常见错误

必须有 DAG、状态迁移、重复消息、乱序进度、取消、恢复、每种 Agent 失败、确认超时和并发修改测试。阻断错误包括：子 Agent 直连用户或数据库、自然语言代替结构化状态、未标识部分结果、以全量重生代替局部修改、按前端状态决定退款、Schema 修改未通知消费者。

## 6. 交付检查清单

- [ ] 架构图、ADR、状态机与错误码已评审
- [ ] Agent/OpenAPI 契约版本、样例和兼容策略已冻结
- [ ] 任务重试、租约、进度和恢复可观测
- [ ] 冲突/确认/降级规则可测试且面向用户可解释
- [ ] M1/M2 质量 Gate 的机器指标已交给 R7

## 7. 逐步开发提示词

### R1-00 建立架构总规则

```text
请只读取资料并创建/完善 CLAUDE.md、docs/architecture/总体架构设计.md、docs/architecture/ADR/README.md。
固化总控唯一对外、六个 Worker 对内、Java 业务后端唯一写库、Python Agent 只能经 REST、MySQL/Redis/对象存储边界、任务状态机、契约先行、事实数据不得由 LLM 编造、版本不可变、局部修改最小化和积分结算触发点。用 Mermaid 绘制上下文、容器、首次生成和修改链路。不要写业务代码。
```

### R1-01 冻结 Agent 和跨栈契约

```text
请校验 agents/ 下 7 个 Agent 的 input/output Schema、prompt 和 docs/03-多智能体系统规范.md。
创建 contracts/agent-contract-index.md、contracts/openapi/agent-business.yaml 和每个契约的成功/partial/degraded/failed 样例。补充 task_id、trace_id、request_id、schema_version、source_metadata、generated_at 的注入规则；不得让模型伪造来源。运行 Draft-07、OpenAPI 和消费者兼容性测试，发现破坏性问题先列清单不要私自改语义。
```

### R1-02 实现任务状态机与持久化骨架

```text
只实现 planning_task、task_step、task_event 的迁移、领域状态枚举和合法迁移服务。
覆盖租约、心跳、attempt_no、超时、取消、重试、死信、部分成功和终态幂等；同一 task/step 的重复消息不得多写结果。编写 MySQL 集成测试验证乐观锁、并发领取和服务重启恢复。暂不接入真实 Agent。
```

### R1-03 实现首次生成 DAG

```text
在 Mock Worker 上实现需求解析→资讯/天气/预约并行→日级分配→路线→餐住→质量校验→整合的 LangGraph 图。
每一步保存脱敏输入哈希和输出引用，支持从任一步骤恢复；子 Agent 失败按契约降级并汇总 degraded_fields。写固定案例测试并验证硬约束优先级，暂不实现局部修改。
```

### R1-04 实现确认、取消和局部调度入口

```text
增加 AWAITING_CONFIRMATION、CANCELLED、REFUNDED 状态及前置条件。
实现从修正 Agent 接收 affected_days、affected_agents、changes、needs_confirm；确认前不创建发布版本，确认后只调度影响范围，未影响快照保持不变。补充跨日冲突、用户取消、重复确认和旧版本提交测试。
```

### R1-05 总控验收与回放

```text
建立任务回放 API/脚本，仅输出脱敏的步骤时间线、输入输出哈希、来源摘要、耗时和降级字段。
禁止回放脚本重新扣积分或调用真实供应商。用故障注入测试模型非法 JSON、天气超时、路线失败、Redis 重启和 Worker 崩溃，输出 Gate 报告后停止。
```
