# 04 R4 LLM 网关、修正与版本规范

## 1. 责任边界

R4 主责统一 LLM 网关、模型路由、受控 JSON 修复、调用留痕、交互修正 Agent、多方案策略和版本管理；不拥有业务余额写入权，也不直接调用供应商地图/天气/POI。

## 2. LLM 网关

- 每次调用由服务端选择模型/端点、温度、超时、最大输出、预算和并发配额；用户不能传模型名、系统 Prompt 或供应商参数覆盖系统策略。
- 用户文本是数据，不是指令。Prompt 采用明确分隔、最小上下文、工具结果白名单，防“忽略规则/泄露密钥/编造票价”等注入；将 Prompt 模板、模型别名、工具/Schema 版本、输入哈希、token 和费用摘要写入审计元数据。
- 输出处理顺序：提取 JSON→解析→Schema 校验→有限格式修复→携带校验错误重试一次/按配置重试→failed。不能为通过 Schema 自动补事实、改数值或无限重试；原始响应只以脱敏哈希或受控调试留存。

## 3. 修正 Agent 与多方案

- 首先判别问答/修改/歧义；问答不得建新版本、扣费或触发子 Agent。修改输出 `base_version_id`、影响日期、受影响 Agent、原子变更集和 `needs_confirm`。
- 用户显式锁定项、必去点、已确认预约和跨日硬约束为保护项。波及保护项、影响范围不清或有硬冲突时只生成确认问题；确认前不得写计划。
- 多方案只在已共享、未过期、相同来源快照上变化编排/路线/预算档策略；每套都须独立跑质量校验并明确差异，禁止只改摘要文案冒充不同方案。

## 4. 不可变版本

- 版本写入采用乐观锁；持久化 `parent_version_id`、schema/model/prompt 版本、来源快照引用、变更集、创建原因、创建者、状态和 hash。任何回滚都是以历史快照创建新的当前版本。
- 未受影响区块保持原 JSON/业务语义不变；通过 JSON Patch 或领域级 diff 验证。版本上限不删除已发布版本、审计和被社区引用快照。
- 任务失败或用户拒绝确认不创建已发布版本；并发客户端基于旧 ETag 修改时返回 409 和 diff，不能最后写入者覆盖。

## 5. 验收

需有模型非法输出、Prompt 注入、超时/限流、重复重试、问答不改版本、单点/单日/跨日修改、确认拒绝、并发编辑、回滚和多方案共用数据的测试。阻断项：模型写事实字段、无来源自动修补、原地改历史版本、全量重生成伪装局部修改、未审计的模型成本。

## 6. 逐步开发提示词

### R4-00 LLM 网关接口

```text
请只实现统一 LLM Gateway 接口、模型路由配置、预算/并发/超时、脱敏调用日志和 Mock Provider。
供应商 Key 只能从环境注入；用户不能覆盖系统 Prompt、模型和安全参数。日志保存模型别名、版本、耗时、token/费用汇总、输入哈希和状态，不保存密钥或完整私密行程。补充超时、429、空响应和重试上限测试。
```

### R4-01 结构化输出和安全防线

```text
实现 JSON 提取→解析→Schema 校验→有限格式修复→按配置重试的流水线。
修复只处理引号、包裹和多余 Markdown 等格式问题，不能补事实值或缺失来源；连续失败返回 failed。用 Prompt 注入、恶意工具结果、超长输入、非法枚举和重复重试测试，并保留脱敏哈希供回放。
```

### R4-02 问答/修改意图分类

```text
实现交互入口的询问、修改、歧义三分类。询问只读当前版本/知识库，不建版本、不扣积分；歧义返回澄清问题；修改输出 base_version、affected_days、affected_agents、changes、needs_confirm。
测试“问票价”“删第二天一个景点”“把两天互换”“忽略前面规则”等边界，不能由模型直接执行写操作。
```

### R4-03 版本与最小变更

```text
实现不可变 itinerary_version、version_diff、乐观锁/ETag、保护字段和 JSON Patch/领域变更合并。
未影响日期必须保持语义一致；波及必去、预约、用户锁定项或跨日冲突转确认态。回滚只能创建新版本，不能删除历史。补并发修改、拒绝确认、Agent 部分失败、回滚和版本上限测试。
```

### R4-04 多方案与成本控制

```text
实现 1~3 套方案策略，采集类 Agent 结果共享，只有编排/路线/预算档按差异重跑。
每套方案保留来源快照、质量分、差异摘要和总耗时/费用；验证方案数量不能被前端伪造，重复提交不会重复调用或扣费。输出与 R7 评估集的对比报告。
```
