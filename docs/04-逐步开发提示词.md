| 项目 | 内容 |
|---|---|
| 版本 | V2.0 |

| 工期 | M0 1 周、M1 2 周、M2 3 周、M3 3 周、M4 2 周 |

## 1. 使用规则

1. 每次只执行一个步骤的提示词，并在末尾追加第 5 节“通用收尾提示词”。
2. 必须按依赖顺序执行；表中写明“可并行”的步骤只能在共同依赖通过后并行。
3. 每步完成后将 Gate 证据写到 `docs/progress/Sxx.md`。没有真实测试证据不得标记完成。
4. 遇到文档冲突、外部账号缺失或无法决定的业务规则，记录 `PENDING` 并停止受影响部分；不受影响的 Mock、测试和文档可以继续。
5. 不得为了让流程继续而伪造 API、测试、来源、截图、性能数字或完成状态。
6. 需求范围以 `02-开发决策基线.md` 的 P0/P1/P2 为准。M2 Gate 未通过时不得进入 P1。

## 4. 分步提示词

### S00 - 仓库、公共规则与追踪矩阵

```text
只建立工程治理，不实现业务。确认当前目录为 Git 仓库；若不是则初始化。检查并保留现有 CLAUDE.md、.editorconfig、.gitignore、.env.example 和 docs/ 文档结构，创建 contracts/、backend/、agent-service/、frontend/、tests/、deploy/ 目录骨架。
校验 docs/README.md 中需求、决策、系统规范、执行提示词和角色规范的链接及权威范围。旧 25 步文档、重复文档包和 .bak 已删除，不得重新创建或作为执行入口。
创建 docs/需求追踪矩阵.md、docs/需求澄清与决策清单.md、docs/progress/README.md。追踪矩阵覆盖需求 2.x、P0/P1/P2、负责人、依赖、接口、表、测试和验收。
验收：目录和链接有效；无真实密钥；git status 可用；S00 证据完整。
```

### S01 - 范围审计、架构 ADR 与状态机

```text
只做设计，不写业务功能。根据需求和开发决策基线，创建总体架构、上下文图、容器图、首次生成 DAG、局部修改 DAG、数据流和降级图。
创建 ADR：Java/Python 边界、MySQL 唯一写方、事务 Outbox + Redis Streams、SSE、来源快照、不可变版本、缓存所有权、积分一致性、Chroma、对象文件和裸机部署。
定义 planning_task 合法状态、迁移操作者、前置条件、超时、取消、恢复和终态幂等。固定硬约束优先级和确认条件。
验收：所有 ADR 为 Accepted；无待定二选一；状态迁移表和失败路径可测试。
```

### S02 - 冻结 Agent Schema 与双栈契约

```text
审查 agents/ 下所有 input/output Schema 与 prompt。服务输出统一包含 schema_version、task_id、trace_id、request_id、generated_at、status；partial/degraded 强制非空 degraded_fields，failed 强制 error_code/message 且不强制成功载荷。
路线使用 poi_id、城市、经纬度和坐标系；天气带来源与取得时间；景点带知识条目/chunk/时效；餐住带 poi_id/坐标/价格口径；预约带币种、生效期、时区和 stale；修正带 intent、base_version_id 和确认信息。
创建 contracts/openapi/agent-business.yaml、契约索引、错误码目录，以及每个 Agent 的 success/partial/degraded/failed 示例。系统字段由网关注入，模型不得生成。
建立 Draft-07、OpenAPI、示例和 Java/Python 消费者契约测试。验收：所有契约测试通过且无未说明的破坏性变更。
```

### S03 - 工程骨架、CI 与本地环境

```text
按 ADR 初始化 backend（Java 21/Spring Boot 3/Maven）、agent-service（Python 3.11+/FastAPI/LangGraph/Pydantic v2）和 frontend（Vue 3/Vite/TypeScript/Pinia/Element Plus）。不实现业务。
配置统一格式化、lint、单测、依赖锁定、健康检查、配置分层和 Mock profile。开发 Compose 只启动 MySQL/Redis/Chroma 所需环境；提供不依赖 Docker 的说明。
CI 至少运行 Java/Python/前端构建、单测、Schema/OpenAPI、Flyway 空库、密钥和依赖扫描。验收：新环境按 README 一条路径启动并全部构建通过。
```

### S04 - 数据模型与 Flyway

```text
根据已冻结契约设计 ER 图、数据字典和首版 Flyway。覆盖账号/会话、行程/版本/diff、任务/步骤/事件/outbox、Agent 结果/来源快照、POI/知识/规则、积分账户/流水、社区治理、偏好、通知、导出和审计。
定义主键、owner、唯一键、乐观锁、UTC 时间、软删除/保留期、索引和敏感字段。积分用整数且流水只追加；货币用 currency + amount_minor；可查询字段不能只藏在 JSON。
执行空库升级、重复启动和从上一版升级测试。验收：迁移可重复验证，已发布脚本不被改写。
```

### S05 - 评估集框架与 TripStar 基线

```text
只建立评估方法和脱敏样例，不复制 TripStar 代码、Prompt、图片或数据。创建至少 30 个案例的模板，先填充 10 个北京案例，覆盖硬约束、同名 POI、闭馆、天气窗口、过期规则、无数据和局部修改。
定义机器指标、人工评分表和固定运行条件；保存输入、输出摘要、证据、时延和费用，不保存真实用户数据。
若本机没有 TripStar，只记录 PENDING 和可复现实验计划，不阻塞本项目 Mock 开发。验收：指标计算脚本可在固定假数据上运行。
```

### S06 - 城市、来源台账与北京最小数据集

```text
按开发决策基线建立 10 城清单和来源台账，先完成北京最小数据模板。资料字段包含来源 URL、许可、录入/复核人、核验时间、有效期、状态、城市、内部 POI ID 和别名。
禁止未授权抓取、许可不明图片和模型生成政策。同名、坐标冲突和来源冲突进入人工队列。
验收：北京试点数据能覆盖 S05 案例所需景点；未核验内容保持 draft，不能被 Agent 读取为事实。
```

### S07 - 开题演示前端

```text
在 S03 前端骨架上实现开题演示：输入表单、模拟进度、时间轴、地图占位、方案对比和社区静态样张。只使用与 S02 契约一致的本地 fixture。
页面持续显示“演示数据，未接入真实接口”，不得把 Mock 票价、时长和政策描述成真实。实现组件规范、响应式布局、键盘操作和空/错/加载状态。
输出 Playwright 截图和演示动线。验收：桌面和移动视口无溢出、遮挡，Mock 开关不可在生产配置误启用。
```

### S08 - 公共后端、认证与核心积分账务

```text
实现统一响应/problem detail、trace、审计、USER/ADMIN 注册登录刷新退出、密码哈希、限流锁定和资源归属授权。
同时实现任务所需最小积分核心：quote、预扣、确认、失败退款、赠送；使用只追加整数流水、唯一 business_reference 和幂等键。前端金额/角色/user_id 均不可信，不接真实支付。
测试令牌吊销、IDOR、并发刷新、并发临界余额、重复预扣/退款和崩溃恢复。验收：账务守恒且 S11 可依赖稳定接口。
```

### S09 - LLM 网关

```text
实现 OpenAI 兼容 LLM Gateway、Mock Provider、模型路由、超时、并发、预算和脱敏调用元数据。Key 仅从环境读取。
输出处理固定为 JSON 提取、解析、Schema 校验、有限格式修复、携带错误重试一次、failed；不能补事实值或猜枚举。用户内容只能作为 data，工具结果也视为不可信输入。
测试非法 JSON、Markdown 包裹、429、超时、空响应、注入、重试上限和费用统计。真实账号未通过最小调用时，只能标记 Mock 验收。
```

### S10 - 第三方适配器、缓存与 Mock

```text
实现高德地图/路径/POI、和风天气、LLM 的端口和 Mock。统一供应商别名、超时、重试、熔断、限流、配额、缓存版本、TTL、负缓存和降级错误码。
路线键包含坐标系/起终点/方式/时段；天气返回供应商实际预报窗口；POI 返回唯一 ID、坐标、城市、类别、数据时间。禁止仅按中文名缓存或把失败鉴权缓存为业务空结果。
真实 Key 缺失时完成 WireMock/MockTransport 测试并记录外部账号 Gate。验收：超时、429、空结果、脏数据和缓存过期均有确定行为。
```

### S11 - 任务、Outbox、Redis Streams 与 SSE

```text
实现 planning_task/task_step/task_event/outbox、Redis Streams Consumer Group、Worker 租约心跳、attempt_no 幂等和死信处理。业务后端创建任务、报价预扣和 outbox 必须处于同一数据库事务。
实现 SSE 鉴权、单调 sequence_no、断线补拉和终态关闭；前端不得直连 Redis。进程恢复从最后成功且来源仍新鲜的步骤继续。
先使用 Mock Agent 跑状态机。测试重复投递、乱序、消费者崩溃、Redis 重启、取消和终态重复回调。
```

### S12 - 路线 Agent 与排序算法

```text
实现 POI 消歧、地图矩阵、时间窗可行性和确定性贪心 + 2-opt。输入必须是 poi_id、城市、坐标和坐标系；同名/缺坐标/跨城市不猜测。
输出逐段 ID、方式、距离、时长、来源时间和 is_estimated；通勤、游玩、排队和用餐时间分离。三级降级为精确缓存、显著标注的直线估算、不可用；估算不能通过硬可行性 Gate。
测试闭馆、午休、重复点、固定起终点、必去点、无解和地图失败。
```

### S13 - 天气 Agent

```text
实现按城市标准 ID、供应商时区和实际 forecast_horizon_days 查询。窗口内为 forecast，窗口外只能返回 climate_statistics，不能编具体降雨概率。
每条天气包含 date、温度、天气、降水、data_type、source_record_id、retrieved_at、valid_until。建议只能引用已返回事实；失败不得默认晴天。
测试窗口边界、跨月、时区、极端天气、空结果、429 和过期缓存。
```

### S14 - M1 真实端到端前端

```text
将 S07 fixture 切换为 S08-S13 真实接口，跑通北京单城三日输入、报价、提交、预扣、SSE 进度和结果展示。
展示来源、更新时间、预报/统计/估算/未知、排队/待确认/部分成功/失败/取消/退款。预算统一 currency/amount_minor 和总额/人均/区间口径。
完成 M1 Gate 测试；未配置真实供应商时不得宣称真实端到端通过。
```

### S15 - 知识库、规则库、运营工具与 RAG

```text
实现内部 POI/别名、景点知识、chunk、来源、预约规则的草稿、复核、发布、停用和回滚。所有状态变化审计。
RAG 只检索已发布、城市匹配、未过期内容，返回 knowledge_id/chunk_id/source。规则包含票种、currency/amount_minor、生效期、适用人群、渠道、放票时区、例外和 stale。
先导入 S06 北京最小集。测试同名合并、冲突、过期、低相似度、注入文本和版本回滚。
```

### S16 - 景点资讯 Agent

```text
只读 S15 已发布知识库，输出玩法、建议时长、最佳时段、避坑、热度及逐项来源。无记录返回 unknown 空卡，不得用模型通识补事实。
偏好只改变已召回内容的排序和表达，不能改写事实。测试空召回、过期、冲突、同名、低置信度和引用完整率。
```

### S17 - 预约规则 Agent

```text
只读已发布规则，输出预约要求、票种、金额、渠道、生效期、时区、核验时间和 stale，并生成可去重的提醒候选。
跨月、非工作日、时区和已错过日期必须正确；缺规则或 stale 只能返回“暂未收录/请以官方为准”。测试冲突、回滚、重复输入和过期。
```

### S18 - 餐饮住宿 Agent

```text
只消费合法 POI 结果和路线信息。候选包含 poi_id、城市、坐标、类别、价格口径、数据时间和 detour_min；每餐正常状态为 2-3 个并按顺路性排序。
无价格返回区间或 unknown，不编数字；忌口等敏感偏好不进入公共画像。测试 POI 空/过期/同名、绕路过长、跨城和超时。
```

### S19 - 日级编排、冲突消解与最终 Plan

```text
实现固定 DAG：需求解析和预检；资讯/天气/预约并行；日级分配；逐日路线并行；餐住；质量校验；整合；创建不可变版本。
硬约束优先级采用 S01 ADR。最终 Plan 的总览、逐日段、预算和事实字段必须符合 S02 契约并引用来源快照；阻断冲突转 AWAITING_CONFIRMATION，不得私删必去点。
质量检查覆盖时间重叠、闭馆、可达、预约、预算、来源和过期。测试每个子 Agent 的 partial/degraded/failed。
```

### S20 - 问答、局部修改、版本、回滚与多方案

```text
先分类 query/change/ambiguous。query 不建版本、不扣费；ambiguous 只返回澄清问题；change 必须携带 base_version_id、锁定项、affected_days/agents、原子变更和 needs_confirm。
确认前不写新版本；修改按 ETag 乐观锁，只重跑白名单范围。版本保存 parent、变更集、来源、schema/model/prompt、hash；回滚创建新版本。
多方案共享同一新鲜采集快照，只重跑真正差异部分。测试旧版本 409、确认拒绝、并发修改、未影响区块保真和重复扣费。
```

### S21 - 修改、确认与 diff 前端

```text
实现统一问答/修改入口、澄清、保护项、确认弹窗、affected scope、版本时间线、结构化 diff、回滚和 409 冲突处理。
问答不得显示已修改；确认前不乐观更新。测试拒绝、重复确认、回滚、并发冲突、弱网和失败重试。
```

### S22 - 降级收口、评估与 M2 Gate

```text
使用 S05 至少 30 个固定案例运行全链路，输出硬约束、来源、Schema、路线、过期提示、局部保真、降级、时延和成本指标。
补齐取消、恢复、确认超时、重复/乱序消息和所有 Agent 故障；终态只结算一次。与 TripStar 只做相同脱敏输入的人工摘要对比。
逐项核对开发决策基线 M2 Gate。任何阻断项未通过则修复并重跑，不得进入 S23。
```

### S23 - 社区、榜单与治理

```text
实现发布、动态流、点赞、评论、收藏、举报、复用和分类榜单。先发后审，但发布前执行归属、频率、敏感词和文件安全检查。
榜单和动态流共用内容及治理状态；下架后公开 API、搜索、缓存和榜单同时不可见。复用去除私密偏好和精确住宿信息。
测试刷赞、重复互动、越权、XSS、恶意图片、下架缓存和并发计数。
```

### S24 - 历史、偏好分析与记忆

```text
实现历史筛选、再来一单、版本演进；偏好统计由 SQL/离线规则生成，LLM 只写画像文案。少于 3 条历史不输出画像。
偏好为带来源、置信度、权重和最后使用时间的软约束，不覆盖本次显式输入；用户可以查看、删除和清空，不进入公开榜单。
```

### S25 - 钱包完整体验与对账

```text
基于 S08 核心账务实现模拟充值、余额/流水页面、失败退款展示、管理员调整和定时守恒对账。继续禁止真实支付。
所有操作以服务端 quote 和幂等键为准。测试重复点击、并发余额、退款重试、管理员越权和对账异常告警。
```

### S26 - PDF/ICS 与站内提醒

```text
实现异步 PDF/ICS 导出、所有者授权、短期下载链接、水印、审计和过期清理。ICS 正确处理 UID、时区、转义和全天事件。
实现预约与天气站内提醒，按规则时区去重和取消；天气仅进入真实预报窗口且结论显著变化时触发。防 IDOR、路径穿越、SSRF 和恶意图片。
```

### S27 - P1 前端与个人主页

```text
禁用 v-html；URL/Markdown 白名单；不在 localStorage 保存刷新令牌、完整私密行程或导出链接。完成移动端、键盘、大字号、空态和弱网 E2E。
```

### S28 - 管理员后台

### S29 - E2E、安全、性能与故障演练

```text

检查 OWASP API、IDOR、JWT/CSRF/CORS、注入、XSS/SSRF、上传、Prompt 注入、依赖、许可证和密钥；按 10 并发记录 P50/P95、队列、缓存、token、数据库和磁盘。
注入模型非法 JSON、供应商 429、Redis/MySQL 短暂故障、Worker 崩溃、重复事件、积分确认后崩溃。阻断项全部关闭后才通过。
```
