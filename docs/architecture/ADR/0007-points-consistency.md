# ADR-0007：积分一致性与终态结算

- 状态：Accepted
- 日期：2026-09-20
- 决策者：项目负责人，R1，R5

## 上下文

生成任务跨事务、队列和 Worker，重复消息或崩溃不能导致重复扣退。部分成功的结算口径需要明确。

## 决策

积分为整数，只追加流水；quote、reserve、confirm、refund 均由 Java 服务端计算并使用唯一业务引用。创建任务、预扣和 Outbox 同事务。`SUCCEEDED` 确认预扣；仅当存在可用且可追溯版本时，`PARTIAL` 确认原预扣；无可用版本的 `FAILED/CANCELLED` 全额退款并最终进入 `REFUNDED`。问答、澄清和执行前取消不收费。

## 后果与验证

失败与退款可能短暂异步，但最终状态可追踪。测试临界余额并发、重复预扣/确认/退款、版本提交后崩溃和退款消费者重启，断言余额守恒且每个业务引用最多一条有效经济流水。

## 替换与回滚

费率或部分成功政策变化必须版本化 quote 和新 ADR，不改历史流水；错误结算用补偿流水，不 UPDATE/DELETE。
