# ADR-0011：确定性硬约束与人工确认

- 状态：Accepted
- 日期：2026-09-20
- 决策者：R1，R2，R4

## 上下文

用户必去点可能与闭馆、预约、可达、天气或预算冲突。LLM 自行取舍会破坏用户意图和可解释性。

## 决策

固定优先级为：显式用户硬约束，闭馆/预约/开放时间，可达与时间窗，天气安全，预算硬上限，软偏好。优先级只决定如何形成选项，不能让高优先级绕过客观不可行。波及必去/锁定/已确认预约、跨日硬冲突、影响范围不清或多解需用户选择时进入 `AWAITING_CONFIRMATION`；确认前不写版本。身份、来源、Schema 和安全门禁不可由用户绕过。

## 后果与验证

部分请求会多一次交互，但不静默违约。固定案例测试必去闭馆、预算无解、旧版本确认、重复确认和确认超时；选项必须带影响范围和来源。

## 替换与回滚

优先级或确认触发器变化必须新 ADR、更新评估集并重跑硬约束与局部保真指标。
