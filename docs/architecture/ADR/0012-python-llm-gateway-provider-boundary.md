# ADR-0012：Python 统一 LLM Gateway 的供应商访问边界

- 状态：Accepted
- 日期：2026-09-20
- 决策者：项目负责人（裁决采用方案二）

## 上下文

项目采用 Java Spring Boot 与 Python FastAPI 双栈架构。Python
负责 Agent 编排、LLM 网关和算法层；Java 负责业务后端、业务事实和
MySQL 唯一写入。

此前部分讨论提出由 Java 独占模型供应商访问出口，但现有总体架构和
开发决策已经将 LLM 网关放在 Python Agent 服务中。若继续要求所有模型
调用经过 Java，将与 Python LLM 网关职责、LangGraph 生态和现有 S10
适配器实现产生冲突。

## 决策

1. Python Agent Service 内的统一 LLM Gateway 可以通过适配器直连
   OpenAI-compatible 模型供应商。
2. 只有统一 LLM Gateway 可以访问模型供应商；普通 Agent、业务代码、
   前端和用户请求不得绕过 Gateway 直接调用供应商。
3. 供应商 Base URL、API Key、真实模型 ID、预算、并发、超时、重试和
   安全参数只能从服务端配置或服务端策略注入。
4. 用户不能覆盖模型、供应商端点、System Prompt、温度、最大输出、
   预算、超时或重试策略。
5. Java 仍是身份、任务、行程、版本、积分、审计和 MySQL 业务数据的
   唯一写方；本 ADR 不授权 Python 直接写业务数据库。
6. LLM 调用必须经过统一的错误归一化、超时和有界重试、输入哈希及
   脱敏调用留痕。
7. 供应商原始响应、API Key、Authorization Header 和完整私密 Prompt
   不得写入仓库、普通日志或业务数据库。
8. `LLM_MODEL` 在没有正式别名表之前，解释为服务端配置的供应商模型
   标识；用户不可传入或覆盖该值。后续增加产品级模型别名时，必须新增
   配置映射和测试，不得由用户直接指定供应商模型 ID。

## 责任边界

- R4：统一 LLM Gateway、模型适配器、错误归一化、JSON 处理、调用留痕
  和相关测试。
- R1：Agent 编排、调用契约、模型使用场景和安全策略评审。
- R5：高德、和风天气及其缓存、限流、错误解析；如使用 LLM，仅通过
 R4 的统一 Gateway，不另建供应商直连。
- Java 业务后端：业务数据、身份、任务、版本和 MySQL 写入。
- 项目负责人：真实供应商账号、预算和最小调用批准。

## 后果

Python 服务需要安全注入供应商配置，并承担模型适配和调用治理责任。
Java 不需要新增一套重复的 LLM 供应商适配器，但仍可通过内部业务接口
调用 Agent 服务。

该决策不改变地图、POI、天气或公交路线的责任划分。公交路线是否属于
S10 仍由 R1、R2、R5 根据路线契约共同确认。

## 验证

必须验证：

- 供应商成功响应归一化；
- 401/403、429、5xx、超时、空响应和脏响应；
- 重试次数有界；
- 用户请求不能覆盖模型和供应商参数；
- API Key 不出现在错误、日志和审计元数据；
- 真实账号最小调用仅在获得正式配置后执行。

当前 MockTransport 和离线质量门禁只能证明协议适配，不证明真实供应商
连通性、配额、延迟或性能。

## 替换与回滚

若项目改为 Java 独占 LLM 供应商访问出口，必须新增 Accepted ADR，
将本 ADR 标记为 Superseded，并同步修改 Python Gateway 契约、配置、
测试、部署文档和 S10 验收记录。不得直接删除或原地改写本 ADR。
