# S01 范围审计

| 项目 | 结论 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-09-20 |
| 输入基线 | 需求 V1.1、开发决策 V2.0、Agent Schema/Prompt、S00 追踪矩阵 |
| 当前范围 | 只冻结架构、状态机、约束和 ADR，不实现代码、接口或表结构 |

## 1. 权威范围

1. 业务目标和功能边界以 `../01-需求与整体设计.md` 为准。
2. 技术、优先级、数据、计费、质量和外部账号 Gate 以 `../02-开发决策基线.md` 为准。
3. Agent 机器输入输出当前以 `../../agents/` 为基线；S02 才完成审查、样例和 OpenAPI 冻结。
4. 全局步骤和依赖只以 `../04-逐步开发提示词.md` 为准。
5. 本目录只约束架构实现，不替代 S02 的接口契约或 S04 的数据模型。

## 2. 范围分层

| 层级 | 本期能力 | 进入条件 | 本次处理 |
|---|---|---|---|
| P0 | 账号基础、北京单城三日、七 Agent、来源、局部修改、不可变版本、基础前端、评估与可重复部署 | S00-S22 依赖 Gate | 冻结架构边界和状态机 |
| P1 | 多方案、社区/榜单、历史/偏好、钱包体验、PDF/ICS、站内提醒、管理员后台 | M2 Gate 通过 | 只预留边界，不提前实现 |
| P2 | 长图、知识图谱、本地模型混合、社区积分激励、复杂报表 | P0/P1 不受影响且另行验收 | 不进入当前关键路径 |
| 范围外 | 真实支付、预订闭环、内容平台抓取、多人实时协作、行中定位、境外城市 | 不进入本期 | 不设计伪接口或占位实现 |

核心积分的报价、预扣、确认和失败退款是 P0 任务一致性的基础设施；模拟充值、钱包页面、管理员调整和对账属于 P1 完整体验。

## 3. 服务与数据边界审计

| 边界 | 允许 | 禁止 | 责任 ADR |
|---|---|---|---|
| Web/前端 | 调用 Java REST，订阅 Java SSE，提交用户命令 | 直连 Agent、Redis、MySQL 或供应商 | ADR-0001、0003 |
| Java 业务后端 | 鉴权、归属、任务/版本/积分事务、Outbox、SSE、审计 | 信任前端金额/角色/版本；让 Python 写业务表 | ADR-0001、0002、0007 |
| Python Agent 服务 | 经 OpenAPI 领取上下文、编排 Agent、回写结构化步骤结果 | 直连 MySQL 业务表；让模型生成系统字段或事实 | ADR-0001、0004、0008 |
| 供应商适配器 | 高德/和风/LLM 的超时、限流、缓存和来源摘要 | 将鉴权失败缓存成业务空结果；保存原始敏感响应 | ADR-0004、0006 |
| 数据存储 | MySQL 业务事实、Redis 队列/缓存、Chroma 向量、受控对象目录 | 把缓存、向量库或对象目录当业务事实来源 | ADR-0002、0006、0008、0009 |

## 5. 冲突与决策审计

- 未发现会阻塞 S01 的文档冲突。
- 金额实现采用更具体的冻结口径 `currency + amount_minor`，不采用公共规范中泛化的 `DECIMAL(18,2)` 选项。
- `PARTIAL` 结算口径已由项目负责人于 2026-09-20 确认：仅在创建可用且可追溯版本后进入 `PARTIAL`，并确认原预扣；未产生可用版本的 `FAILED/CANCELLED` 全额退款。
- 外部账号、TripStar 环境和部署机 `PENDING` 不阻塞纯设计步骤；仍按 `../需求澄清与决策清单.md` 指定步骤阻塞真实验收。

## 6. S01 出口

- 架构图、状态机、硬约束和 11 项 ADR 均为 `Accepted`。
- 没有未决二选一；逻辑接口与数据实体均显式留待 S02/S04 机器冻结。
- 失败、超时、取消、重复、乱序、恢复、确认和终态结算均有可测试规则。
