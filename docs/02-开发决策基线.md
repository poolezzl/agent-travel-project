## 1. 文档权威顺序

不同文档只在自己的范围内权威，不再使用笼统的“某文档整体优先”：

1. `01-需求与整体设计.md`：业务目标、功能范围和非功能目标。
2. 本文：已冻结的产品、技术和运维决策；与需求文档冲突时先停止并发起决策变更。
3. `agents/**/*.schema.json` 与 `contracts/openapi/*.yaml`：机器接口的唯一事实来源。
4. `04-逐步开发提示词.md`：唯一全局执行顺序和阶段 Gate。
5. `roles/00-*.md` 与 `roles/01-R1` 至 `roles/08-R8`：公共约束和各角色实现细则，不定义另一套全局顺序。

发现冲突时必须记录到 `docs/需求澄清与决策清单.md`，由 R1 和受影响模块负责人确认；不得由编程助手自行选择。

## 2. 本期范围与优先级

- P0（必须完成）：账号基础、单城三日规划、总控/路线/天气/景点/预约/餐住/修正七类 Agent、来源溯源、局部修改、不可变版本、基础前端、评估集和可重复部署。
- P1（P0 通过后实施）：多方案、社区/榜单、历史与偏好、模拟积分、PDF/ICS、站内提醒和管理员后台。
- P2（时间允许）：长图、知识图谱、本地模型混合、社区积分激励和复杂运营报表。
- P0 未通过 M2 Gate 时，不得为赶进度跳到 P1/P2；最终答辩只陈述实际通过验收的能力。

## 3. 固定技术决策

| 决策项 | 决议 |
|---|---|
| 服务边界 | Spring Boot 是业务数据唯一写入方；FastAPI/LangGraph 只经 REST/OpenAPI 读取任务和回写步骤结果 |
| 异步任务 | MySQL `planning_task` 为事实来源；事务 Outbox 发布到 Redis Streams Consumer Group；消费者至少一次投递，业务幂等 |
| 进度通道 | SSE；所有命令走 REST。事件持久化并以 `task_id + sequence_no` 补拉和去重 |
| 数据库 | MySQL 8、Flyway、UTC `DATETIME(6)`、InnoDB、utf8mb4 |
| 缓存/队列 | Redis；队列、缓存、限流使用不同 key 前缀，禁止把缓存当业务事实来源 |
| 向量检索 | Chroma 持久化模式，由单一 Agent 服务拥有；Embedding 默认 `bge-small-zh-v1.5`，可配置替换 |
| 前端 | Vue 3 + Vite + TypeScript + Pinia + Vue Router + Element Plus |
| 进度与状态 | 前端只消费后端状态和 SSE，不直接连接 Agent 服务、Redis 或供应商 |
| 对象文件 | 受控本地目录，元数据写 MySQL，接口预留 MinIO；文件名使用随机对象键 |
| 开发环境 | Windows/Linux 均可；允许 Docker Compose 启动 MySQL/Redis，但不得作为唯一部署方案 |
| 交付部署 | Linux + Nginx + systemd 为主；同时提供 Windows PowerShell 等效启动脚本 |
| 模型接入 | OpenAI 兼容网关；供应商、Base URL 和模型名均配置化。真实联调前必须由团队提供可用账号和预算 |
| 地图/POI | 高德 Web 服务 API；前端高德 JS API 使用独立受限 Key 和安全密钥 |
| 天气 | 和风天气为主；适配器必须返回实际预报窗口，禁止把窗口外数据标成预报 |

## 4. 产品与数据决策

- 首批城市固定为：北京、上海、杭州、南京、苏州、成都、西安、重庆、广州、厦门。M1 只要求北京单城数据闭环，其他城市在 M2/M3 分批补齐。
- 规则超过 30 天未核验即为 `stale`；开放时间、票价等可配置更短有效期。过期数据不能作为确定性硬约束。
- 未覆盖景点不得使用“LLM 通识”补事实。可以输出明确标记的非事实性建议，但景点名称、开放时间、时长、票价、预约、餐住和路线字段必须来自规定数据源。
- 货币统一用 ISO 4217 `currency` + 最小货币单位整数 `amount_minor`；积分使用整数 `points`，二者不得混用。
- 模拟积分定价：新用户 100 积分；1/2/3 套方案分别预扣 10/18/25 积分；一次已确认的局部重规划 2 积分；问答、澄清、失败和用户在执行前取消不收费。
- 数据保留：刷新令牌最长 30 天；任务步骤与脱敏模型调用元数据 90 天；导出文件 24 小时；用户私有历史保留至用户删除；审计和积分流水在课程项目周期内不物理删除。
- 图片只允许用户本人上传或许可明确的官方/CC 素材；记录许可和来源，剥离 EXIF。许可不明的图片只保存外链文字引用，不入库再分发。
- 备份默认写入部署机外的受限目录，MySQL 和对象文件每日一次，保留 7 个日备份；M4 必须完成隔离恢复演练。

## 5. 质量 Gate

| Gate | 必须满足 |
|---|---|
| M0 | 决策清单无阻断项；ADR、状态机、Schema/OpenAPI、示例和契约测试冻结 |
| M1 | 北京单城三日端到端；硬约束满足率 100%；事实字段来源完整率 100%；Schema 合法率 100%；10 并发下 P95 总时延不超过 180 秒、10 秒内出现首个真实进度事件 |
| M2 | 至少 30 个固定案例；端到端通过率不低于 85%；局部修改未影响区块保真率 100%；所有过期、估算和降级可见；P95 局部修改不超过 60 秒 |
| M3 | 生成、修改、导出、分享、复用和积分扣退闭环；账务守恒、重复请求零重复扣退、下架内容零公开缓存残留 |
| M4 | E2E、安全、性能、故障恢复和备份恢复报告齐全；不存在无来源事实、跨用户数据泄露、不可恢复迁移或账务不守恒 |

## 6. 外部账号 Gate

以下值不写入仓库，但进入对应真实联调步骤前必须由项目负责人提供并完成最小调用验证：

- `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`
- `AMAP_WEB_KEY`、`VITE_AMAP_JS_KEY`、`VITE_AMAP_SECURITY_CODE`
- `QWEATHER_API_HOST`、`QWEATHER_API_KEY`

账号未就绪时允许继续开发 Mock、契约和算法，但不得把 Mock 结果记为真实 API 验收通过。
