## 关键设计

- **SSE 手动解析（禁用 EventSource）**：`AccessTokenFilter` 只读 `Authorization: Bearer`，EventSource 无法带该头；故用 `fetch` + `ReadableStream` 逐 chunk 解析 `text/event-stream`，支持 `id:`/`event:`/`data:`、空行分隔、`[DONE]`；按 `sequence_no` 去重、只接受更大序号、断线带 `after_sequence_no` 续传、终态停止重连。
- **无结果接口处理**：`GET /v1/tasks/{id}` 只返回 TaskView，无 plan/trip_version/agent_result，结果区为显式空态（PENDING-S14-01），不渲染 S07 fixture。
- **幂等**：资金/任务类写请求（报价、建任务、取消）生成 `Idempotency-Key`（`crypto.randomUUID()`）；报价同 planCount、建任务同载荷复用同一 key，`forceNewKey` 用于失败重试；认证接口（注册/登录/刷新/登出）不带该头，服务端亦不要求。提交按钮防连点。
- **401 刷新**：http 层 401 时用 refresh token 刷新一次并重放原请求，刷新失败清空会话；令牌只驻内存。
- **金额口径**：积分用整数 `points`；预算 `currency + amount_minor`（整元 ×100），前端不计算积分价格/余额。
- **状态展示**：覆盖 14 态与排队/待确认/部分成功/失败/取消/退款，并提供取消（二次确认，带 `expected_version`）、重试、查看原因（traceId）动作；`degraded_fields` 显式列出。

### 工具链修复记录（如实）

- **vitest 进程池**：默认进程池（forks/threads）在 Node 24.14 + vite 8.3 + vitest 5.0.1 下收集阶段抛 `Cannot read properties of undefined (reading 'config')`（最小 spec 文件可复现，与 S14 代码无关）。改 `vitest.config.ts` `pool: 'vmThreads'` 后全绿。此改动仅测试配置。
- **format:check 行尾（未根治）**：`core.autocrlf=true` 使 Windows 检出文件为 CRLF，`prettier --check`（默认 LF）对既有文件报错。`prettier --write` 只能归一化**当前工作区**，重新 clone/checkout 后仍会恢复 CRLF，因此**不能视为已修复**，也不应据此在验收表里记"通过"。根治方式二选一：团队同意后新增 `.gitattributes`（`* text=auto eol=lf`），或本地改 `core.autocrlf=input` 后重新检出。该改动属仓库级，未在本步骤内擅自提交。
- **e2e 路由拦截**：任务建议的 `page.route('**/api/**')` 会误命中 Vite 开发服务器下的 `/src/api/*` 模块请求导致整页空白，改为 `page.route(/\/api\/v1\//)` 只拦截后端前缀。
