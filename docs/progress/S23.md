# S23 社区、榜单与治理

基线为远端主分支 `9ed8102`。S22 的 30 个案例及 13 项验收均通过，允许进入 S23。对应需求为 2.4、2.6 及公共工程、R5、R8 规范。

## 交付范围

- 登录后发布本人行程的已定稿版本、点赞、取消点赞、评论与评分、收藏、取消收藏、举报和复用。浏览动态流、搜索、评论、详情和分类榜单无需登录。社区页面按 S27 实施。
- 发布先校验归属、频率、敏感词和图片，入库为待审并立即公开。管理员可审核、置顶、取消置顶和下架，发布者可撤回。帖子或评论可被举报，多条举报合入同一未结案件。处置、发布与举报均写审计。
- 动态流、搜索、详情、评论、图片和榜单共用数据库可见状态。下架事务同时隐藏已有榜单派生记录。应用按与控制器一致的路径规则为社区响应设置禁止缓存，包括带路径参数的地址。图片链接五分钟到期，访问时再次检查帖子和文件归属。
- 图片最多三张、每张不超过两兆字节、长宽各不超过 2048。校验格式与声明许可，从解码后的像素重建图片并按随机对象键存储。文件内容保存在受控目录，默认位于用户目录下的 `.agent-travel/community-images`，生产由 `app.community.object-directory` 设置持久盘路径。网关继承应用的禁止缓存响应头，不直接暴露该目录。
- 复用按账号与帖子去重，生成本人私有草稿。草稿保留城市、天数及公开景点顺序，使用本人选定的出发日期，通过本人接口读取。后续生成可将草稿编号作为已有生成接口的 `trip_id`，由用户确认日期和景点后提交。
- 榜单按城市、主题、天数组合过滤，使用热度、用户评分、季节适配、行程质量和估算客流加权，再按发布时间衰减。热度的点赞、收藏、复用和评论按账号去重，评分取同一账号最新可见评分。季节只使用仍有效的知识记录，其余缺失维度显式返回。客流是基于周末、配置节假日与站内热度的估算。
- 榜单可通过 `app.community.ranking-weights`、`app.community.ranking-decay-hours`、`app.community.ranking-minimum` 和 `app.community.ranking-holidays` 调整。管理操作带版本号，重复写入使用请求去重键。默认点赞与收藏共享每分钟 20 次额度，可用 `app.community.reaction-limit` 调整，敏感词由 `app.community.blocked-words` 配置。

| S11 真实数据库测试，独立库并指定迁移目标 V4 | 10 项通过 |
| S11 消息队列测试 | Redis 7.4.11 上 3 项通过 |
| S23 社区集成测试 | 6 项通过，覆盖发布检查与请求重放、刷赞与并发计数、举报及下架后公开读取、榜单筛选及衰减、复用归属与隐私、反向代理缓存。此前已验证从 V4 升级到 V5 |
| 收尾复核 | 在真实数据库复现了规范化后超长标题返回 500。修复后返回 400，前五次发布成功、第六次返回 429。社区集成与迁移检查共 9 项通过，含代理用例 |
| S20 跨服务回归 | 2 项通过。真实后端、智能体进程、数据库及 Redis 7.4.11 互通，使用模拟外部供应商，覆盖并发修改保真及多方案队列处理 |
| 跨服务既有契约校验 | 14 个智能体结构、28 个样例和 S19 行程结构及两个样例通过 |
| S23 接口结构 | 接口规范校验通过，另检查了 17 条操作、路径参数、请求去重头、结构引用和两个样例 |

在 `backend/` 下设置 `S23_IT=true`、`DB_URL`、`DB_USERNAME`、`DB_PASSWORD`，指向一次性测试库，再运行 `mvn -o -Dtest=S23CommunityIntegrationTests -DforkCount=0 test`。测试在库内保留合成记录，图片写入临时目录。

额外设置 `S23_NGINX_EXE` 为 Nginx 程序的绝对路径即可运行代理用例。Nginx 1.28.0 的对照请求由未命中变为命中。社区详情、带路径参数的详情、评论、图片、搜索和榜单重复读取均回源，下架后详情、评论和旧图片链接返回不存在，搜索与榜单移除该条目。

独立子代理复查了权限、事务、脱敏、下架规则和测试证据。根据复查意见加入代理缓存命中对照。

## 回滚与待验证项

- 回滚代码提交后，V5 的新增字段和表可保留，旧版本无需访问它们。备份及还原应包含数据库与图片目录。若回滚应用启动依赖迁移校验，部署时应保留已应用的 V5 脚本原件。
- 隔离代理已验证遵守禁止缓存策略。生产环境的代理配置复验和进程意外终止后的孤立文件巡检按后续部署与故障演练步骤执行。
