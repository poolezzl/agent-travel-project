### 第一次尝试仍未满足项与原因（最终结果见本节末尾追加验证）

> 下面记录的是**仅使用仓库样例、未提供外部天气账号和官方数据**时的第一次尝试；它仍然
> 是真实的 `PARTIAL` 证据。外部账号与官方数据就绪后的最终结果见本节末尾
> “追加验证（外部账号与官方数据就绪后）”，最终任务已为 `SUCCEEDED`。

任务当时为 `PARTIAL`，没有通过改数据或放宽规则凑成 `SUCCEEDED`。逐项原因如下：

1. `weather.2026-11-26`、`days[0].weather`：运行中的 Agent 服务没有可用的和风天气
   凭据（`profile=mock`，仓库无 `.env`，`QWEATHER_API_KEY` 未配置）；`runtime.build_default_deps`
   走 `UnavailableWeatherPort`，天气 Agent 返回 `SOURCE_UNAVAILABLE`，计划中该日天气为
   `unknown`。这是外部账号 Gate，未用任何本地假天气替代。
2. `meals`、`lodging`、`lodging.candidates`：S19 `assemble.py` 向 S18 传入
   `"companion": {}`，而 S18 的 `_validate_preferences` 要求 `companion` 为字符串；S18 返回
   `INVALID_INPUT: companion 必须是字符串`，S19 因此回退为空餐住。复现命令见下；这是跨步骤
   代码缺陷，不在 S06/S15 范围内，未在本分支修改。
3. `cards[2].source`、`points[POI-BJ-003].attraction`、`points[POI-BJ-003].duration`、
   `days[0].segments[1].facts`：运行快照中的天坛公园（`POI-BJ-003`）只有 POI、没有知识条目；
   导入的 S06 样例只覆盖“示例景点甲”一个景点知识。仓库没有天坛的已发布知识，不能用模型
   通识或手写事实补齐。
4. `cards[0].freshness_status`、`cards[1].freshness_status`：运行快照中故宫/国博的
   `retrieved_at` 分别为 2026-10-20、2026-10-10，到 2026-11-25 已超过 30 天新鲜度阈值，
   景点 Agent 按 `stale` 降级。
5. `days[0].reservations[POI-BJ-001]`、`reservations[0].stale`、`timeline[0]` 等：运行快照的
   预约规则 `last_verified` 为 2026-10-20 和 2026-09-01，均已超过 30 天；S17 正确标记
   `stale`。导入样例的规则 `last_verified_at=2026-09-20` 同样已过期，不能靠改日期“变新”。
6. `reservations[2].policy_id`：缺少可匹配的已发布规则/时间线，按 unknown 保留，不补造。
