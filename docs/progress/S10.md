## 关键设计

- 路线缓存键包含缓存版本、供应商、坐标系、起终点、方式和时段；POI 键包含供应商、城市、规范化查询、类别和页码；天气键包含供应商、城市、日期范围和请求窗口；模型请求不进入缓存。
- 路线、POI、天气键严格使用 `cache:v1:route`、`cache:v1:poi`、`cache:v1:weather` 字面命名空间；版本字段、供应商和完整参数均保留，参数使用长度编码后再哈希，防止分隔符注入和拼接碰撞；三类版本前缀支持批量失效。
- 认证失败和配额错误不进入负缓存；空结果、无效响应和脏数据只按短 TTL 负缓存；发布停用可按键失效。
- 路线、天气、POI 默认缓存分别为 7 天、1 小时、30 天，配置值必须为正数；过期项保留来源并先刷新，刷新失败返回带 `stale` 来源和错误码的降级旧值。
- 缓存按键单飞，同一参数并发只允许一次供应商刷新；未知来源新鲜度也显式标为降级。
- 来源保留供应商别名、来源记录号、取得时间、有效期、新鲜度和估算标记；本地 Mock 明确标记 `estimated=true`，天气只返回 Mock 配置的实际预报窗口。
- 超时、429/限流、配额、鉴权、空结果、无效响应、脏数据、熔断和不可用均使用稳定错误分类；重试只针对可重试错误，达到阈值后熔断。
- 根目录契约校验依赖固定为 `PyYAML==6.0.3`、`jsonschema==4.26.0` 及其精确传递依赖；覆盖率报告仅生成报告，项目当前未冻结数字门槛。

## 稳定错误映射

| 场景 | 错误码 | 行为 |
|---|---|---|
| HTTP 401/403 | `LLM_AUTH_FAILED` | 不重试，不伪装为空结果 |
| HTTP 429 限流 | `LLM_RATE_LIMITED` | 确定性失败 |
| HTTP 429 配额耗尽 | `LLM_QUOTA_EXHAUSTED` | 确定性失败 |
| HTTP 400 等请求错误 | `LLM_INVALID_REQUEST` | 不重试 |
| HTTP 5xx | `LLM_PROVIDER_UNAVAILABLE` | 按配置进行有界重试 |
| 网络请求错误 | `LLM_PROVIDER_UNAVAILABLE` | 按配置进行有界重试 |
| 请求超时 | `LLM_TIMEOUT` | 确定性失败，不无限重试 |
| 非法 JSON、空结果或脏结构 | `LLM_DIRTY_RESPONSE` | 不作为业务空结果返回 |

所有错误消息均为本地脱敏消息，不透传供应商响应中的潜在敏感信息。

## R5 真实传输适配器补充（2026-10-22）

### 状态

R5 主责的高德路线、地点和和风天气真实传输代码与离线替身测试已完成；未访问真实供应商网络。真实账号最小调用、供应商套餐参数和真实端到端仍为 `PENDING`，不能视为真实联调或 M1 通过。

### 新增与修改

- 新增 `ProviderHttpTransport`、请求/响应模型、稳定传输异常和 `JavaProviderHttpTransport`。生产传输只允许 HTTPS、禁止自动重定向、限制响应大小并设置连接和请求超时。
- 新增 `RealAmapAdapter`，复用现有路线、地点端口、调用执行器和本地内存缓存；支持驾车、步行和出租车映射，解析供应商状态、距离、时长、起终点和 GCJ02 坐标。
- 高德地点按供应商地点编号去重，跳过缺坐标、类别缺失和跨城市记录；部分脏数据显式降级，全部不可用时返回脏数据错误，空集合只做短时负缓存。
- 新增 `RealQWeatherAdapter`，按标准城市参数、供应商 Host、Key、配置的预报档位和供应商时区请求；只返回供应商实际给出的逐日预报，窗口缺失时显式返回窗口外或脏数据状态。
- 天气逐日记录包含温度、降水概率、天气、`forecast` 类型、来源编号、取得时间和有效期；窗口外不生成晴天、降水概率或气候统计。
- 新增供应商 429 独立错误码，区分本地限流和供应商限流；鉴权、配额、供应商 429 不进入负缓存。
- 真实适配器仅在 `ADAPTER_MODE=real` 时装配，密钥只从环境变量或受限配置读取；模拟模式保持默认。
- 配置新增 `AMAP_BASE_URL`、`AMAP_WEB_KEY`、`QWEATHER_API_HOST`、`QWEATHER_API_KEY`、`QWEATHER_FORECAST_DAYS`、`QWEATHER_ZONE_ID`、`ADAPTER_CONNECT_TIMEOUT_MS` 和响应大小上限。
- 新增 `app.adapters.cities` 非密钥标准城市映射，提供北京、上海、杭州、南京、苏州、成都、西安、重庆、广州、厦门到高德 `adcode`、`citycode` 与和风 `location` 的显式映射；业务入口统一使用 `beijing` 等内部键。
- 新增可注入 `ProviderCallMetrics`，对重试、熔断打开、半开探测、本地限流、配额耗尽和供应商失败计数；默认空实现可在后续替换为持久计量或监控组件。
- `WeatherRecord` 增加逐日新鲜度；缓存读取按每条记录自身 `valid_until` 判断。任一日期过期或未知时，顶层来源取逐日最早有效期并整体降级，不再报告新鲜。
- 和风天气逐日来源编号改为包含标准城市键、日期、供应商别名和实际窗口，例如 `qweather:beijing:2026-10-22:qweather:3d`。
