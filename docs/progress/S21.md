## 接口与 Schema 影响

- 无后端/契约/AI 改动；前端只消费 `contracts/openapi/s20-revisions.yaml s20-v1`。
- 三个接口的实际参数与关键响应处理：
  - `POST /api/v1/trips/{tripId}/revisions/preview`：body 为 `base_version_id` + `etag` +
    `revision_request` + `locked_paths`；返回 `intent`/`status`/`needs_confirm`/`affected_days`/
    `affected_agents`/`changes`/`answer`/`clarification_question`/`summary`。`intent` 判定 query/change/ambiguous。
  - `POST /api/v1/trips/{tripId}/revisions/confirm`：body 同 preview 另加 `confirmed: true` 与
    `confirmation_id`；header `Idempotency-Key` 必须等于 `confirmation_id`。成功 `status: CREATED`，
    `reused` 区分新版本与重复确认；`change_set` 优先作为实际变更集。
  - `POST /api/v1/trips/{tripId}/revisions/rollback/{versionId}`：只带 header `If-Match`（当前最新
    版本 etag），无 body；成功创建新版本，`parent_version_id` 指向回滚前当前版本。
- 读取最新版本依赖 `GET /tasks/{taskId}/plan` 既有语义，不新建任务。

## 关键设计

- 状态机：`idle → previewing → answered | needsClarification | awaitingConfirm → confirming →
  created | conflict | failed`。
- `confirmation_id` 生命周期：预览得到 change 时生成一次（`crypto.randomUUID()`）；重试/连点/弱网
  重发全部复用；文本、锁定项或基准版本变化时废弃重建；成功或明确放弃后清空。
- 确认前不乐观更新：plan 只在服务端 CREATED 后经 `getPlan` 刷新。
- query 永不写状态：不生成 confirmationId、不写时间线、不刷新余额、不改 plan。
- 回滚前强制刷新：先 `getPlan` 取最新 etag 再发 `If-Match`；409 进入冲突流程，不二次自动重试。
- reused 处理：`reused: true` 按「已复用原版本，未重复扣费」渲染，不追加时间线、余额只刷新一次。
- 时间线边界：只记录本次会话内 confirm/rollback 响应产生的版本；跨会话历史以空态呈现并标注
  PENDING-S21-01，禁止编造 version_no 推断历史。
- 未受影响日期：确认成功后对比刷新前后 `days[i]` 深比较，仅真正比较过才显示「已验证未变更」。

## 补充修复（dev-r6-s21 二次提交）

- 回滚入口缺口（P1）：首次 `applyConfirmed` 时若时间线尚无父版本，补一条 `kind:'base'` 的「修改前版本」占位，使「生成后只改过一次」也能对父版本发起回滚；回滚仍先 `refreshPlanOnly()` 取最新 etag 再发 `If-Match`。
- reused 后行程不刷新（P1）：当 `reused` 且 `result.version_id !== planning.plan.version_id`（丢响应后重试）时执行 `refreshPlanAndBalance()`，并向时间线追加 `reused:true` 条目，文案「已同步原确认结果（未重复扣费）」；`version_id` 与当前一致时保持原有仅刷新余额行为。
- 必去点默认保护（P2）：进入 plan 时把 `is_must_visit` 的 segment 路径预填进 `lockedPaths`（用户仍可取消）。

## 检查清单

- 来源/权限：修订接口沿用既有 Bearer 认证与 `http.ts` 401 刷新；前端不自行计算积分/余额。
- 幂等：confirm 的 `Idempotency-Key` 与 `confirmation_id` 一致；重试/连点复用同一 id。
- 并发：确认前不乐观更新；409 走冲突横幅并强制重新预览；回滚前刷新 etag。
- 降级：`plan.degraded_fields` 非空时修订面板顶部保留提示，不因修改成功隐藏。
- 隐私：令牌只在 Pinia 内存；不写 localStorage/sessionStorage；不使用 v-html。
- 日志：错误展示服务端 detail 与 trace 短码，不泄露内部实现。
- 回滚：一律表述为「以历史版本内容创建新版本」，禁止出现「历史被删除」；历史不被删除。
