## 交付范围

- 历史行程：查看、按时间/城市/天数/状态（DRAFT/ACTIVE/ARCHIVED）筛选与搜索；「再来一单」拷贝为新草稿并做隐私清理；版本演进对比（字段级 diff，数据来自 `trip_version` 与 `plan_snapshot`，不新增采集）。
- 偏好画像：五个统计维度（city/theme/pace/budget/season）由规则聚合产出，每条带可解释理由 `reason`；LLM 只负责把维度写成自然语言文案。历史行程少于 3 条时 `preference_summary.eligible=FALSE`，不出画像。
- 偏好记忆库：分权重偏好 + 遗忘机制 + TOP-K 召回，生成成功后提取稳定偏好入库，下次注入 Agent 上下文作软约束。
- 约束：画像仅本人可见，可一键清空（写 `status=CLEARED` + `cleared_at`，不物理删除）；偏好不得覆盖用户当次显式输入；不参与榜单排序等公共场景；忌口等敏感偏好不进入公共画像。

## 数据表

- `user_preference`：`preference_key` + `version_no` 版本链，`value_json`，`source_type` ∈ {EXPLICIT, HISTORY_ANALYSIS, SYSTEM}，`confidence` ∈ [0,1]，`weight`，`last_used_at`，`status` ∈ {ACTIVE, CLEARED}。
- `preference_evidence`：`evidence_hash` 唯一约束（防重复证据），`weight_delta`，`observed_at`，`evidence_json`。
- `preference_summary`：`summary_version` 版本链，`sample_count`，`eligible`，`summary_json`，`generated_at`。数据库约束 `ck_summary_eligible` 已保证 `eligible=TRUE` 时 `sample_count>=3`，所以「少于 3 条不出画像」在存储层就拦住了，业务层按同样规则返回空画像即可。
- `trip` / `trip_version`：历史行程来源，含 `status` 与 `parent_version_id` 版本演进链。

## 关键设计

- 统计维度（`summary_json.dimensions`）走规则聚合 SQL，`summary_json.narrative` 这段画像文案才交给 LLM 写，契约里按这个分工标注了。这样 LLM 碰不到事实数据，延续平台一贯的反幻觉口径。
- 版本化：`user_preference` 与 `preference_summary` 均按 `version_no` 追加，不原地改写历史版本；清空走状态位，不删除。
- 注入边界由 R1 负责，知识侧配合由 R3 负责；偏好作为软约束，冲突时以当次显式输入为准。

## 契约

`contracts/openapi/s24-preference.yaml`：历史行程列表、再来一单、同行程版本对比、偏好画像读取、一键清空、偏好 TOP-K 召回、行程版本列表、按版本读取，共 7 个操作。Schema 为 `HistoricalTrip` / `VersionSummary` / `VersionChange` / `VersionComparison` / `TripVersionSummary` / `VersionDetail` / `ReuseResult` / `PreferenceItem` / `PreferenceSummary`。样例见 `contracts/examples/s24/`（version-compare、history、summary、summary-ineligible、recall、versions、version-detail）。已在 `contracts/README.md` 挂索引。

## 版本演进接口（补齐 PENDING-S21-01 / PENDING-S22-03）

- `GET /api/v1/trips/{tripId}/versions`：按 `version_no` 倒序返回版本摘要，带 `current` 标记、`etag`、`content_hash`、`change_type`；`limit` 夹在 1–100，`offset` 不小于 0。
- `GET /api/v1/trips/{tripId}/versions/{versionId}`：返回该版本完整 `plan`、`summary`、来源列表、降级字段，以及局部修改版本（`change_set`）的 `changeType` 与 `affectedPaths`。
- 归属：仅行程所有者或 `ADMIN` 可读；不存在、已软删除、他人行程统一返回 `404 CONTEXT_NOT_FOUND`，不区分「无权」与「不存在」，避免枚举。令牌缺失返回 `401`。
- 只读：已发布版本不可原地修改，本组接口不写库；响应固定 `Cache-Control: no-store`。
- 实现：`revision/TripVersionController`、`TripVersionService`、`TripVersionRepository`、`TripVersionModels`。跨服务契约先于实现落地，示例与 Schema 已随契约冻结。
- 与同行程版本对比（`GET /versions/compare`，由 R8 在 `!19` 中实现）互补：对比接口回答「两个版本差在哪」，本组接口回答「有哪些版本、某个版本长什么样」。两者共用 `trip_version` 与 `plan_snapshot`，不重复采集。

### 顺带修正的实现缺陷

原 `bump()` 用 `merge(value, count+1, Integer::sum)`，重映射函数会把旧值再叠加一次，同一取值命中 2 次被记成 3 次（1→3→6），导致基于命中条数的权重公式失真。已改为 `merge(value, 1, Integer::sum)`，并加回归测试 `repeatedThemeValueIsCountedOncePerOccurrence`。
