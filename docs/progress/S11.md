# S11 任务、Outbox、Redis Streams 与进度流

## 状态

实现与本地专项验证已完成，等待独立检验线程给出最终结论。真实 Redis Streams 因本机服务版本不足保持待定。成功终态的行程版本创建仍属于后续编排步骤，本步骤只推进到 `ASSEMBLING` 并记录 `TASK_ASSEMBLY_READY`，不伪造可用版本。

## 范围与边界

- 新增 S11 任务契约、查询、取消和进度流，不修改既有 Agent Schema、OpenAPI、ADR 与 `V1` 迁移。
- 任务、报价、预扣、`QUEUED` 状态、幂等事件和 Outbox 在同一 Spring 事务提交；任一步失败整体回滚。
- Worker 分为短事务领取租约、事务外执行、短事务校验并回写结果。执行器持有租约期间由心跳任务续租。
- 过期租约可回收；同一 `task_id + step_name + attempt_no` 只写一条结果；旧租约、旧 attempt、终态后的迟到结果均拒绝并写审计。
- Outbox 至少一次转发至 `queue:v1:task:{task_id}`；重复消息由任务和步骤状态幂等吸收；发布达到上限进入 `DEAD`，任务转 `FAILED` 后使用固定业务引用幂等退款。
- 进度事件先写 MySQL，再通过 SSE 推送；事件编号使用任务内单调 `sequence_no`，支持 `Last-Event-ID` 和 `after_sequence_no` 补拉，终态事件发送完后关闭。
- 任务只接受认证身份作为所有者；`trip_id` 与 `base_version_id` 均校验属于当前用户，修订任务必须带基准版本。
- 请求载荷写入前递归脱敏密钥、令牌、Prompt、联系方式、精确位置和供应商原始响应字段。
- 未实现 S09 完整模型网关、S12 路线 Agent、S13 天气 Agent、S14 前端或后续任务调度业务。

## 配置

- 任务时限、租约、心跳、最大 attempt、Outbox 重试、Redis 连接、协调线程和 SSE 参数均由环境变量配置。
- 本地缓存仍属于 S10；S11 未引入任何外部缓存或将 Redis 作为业务事实源。
- 环境变量样例见 `.env.example`，关键前缀为 `S11_*`、`REDIS_*`。

## 数据与兼容

- 直接复用 `V1__initial_s04_schema.sql` 的 `planning_task`、`task_step`、`task_event`、`outbox_event`、`agent_result`，未新增迁移。
- Redis 队列键严格使用 `queue:v1:task:{task_id}`，与 `cache:`、`rate:` 前缀分离。
- MySQL 是任务、步骤、事件和结算的唯一事实源；Redis 丢失后按 MySQL 状态恢复并重放 Outbox。

真实 MySQL 测试覆盖：

- 同一事务创建任务、报价、预扣、Outbox，并核对余额与流水。
- 模拟执行器完成解析、采集、排期、路线和整理五个步骤，核对事件序号与步骤 attempt。
- 取消任务后只产生一次退款并恢复余额。
- 永久 Outbox 发布失败后任务进入 `REFUNDED`，Outbox 为 `DEAD`。
- `trip_id`、`base_version_id` 跨用户访问被拒绝。
- SSE 从 `Last-Event-ID` 补拉、返回单调事件并在终态关闭。

- 风险：Python 完整 OpenAPI 校验依赖未安装到系统环境；Java 契约测试负责机器解析和关键语义检查，Python 脚本当前执行基础结构校验。

## 回滚

- 回滚 S11 提交即可移除任务 API、Worker、Outbox、SSE、契约、配置和测试。
- 不涉及数据库迁移回滚、业务数据删除、Redis 外部持久数据或真实供应商状态变更。
- 若已启用运行配置，回滚前先关闭 `S11_ENABLED`，避免旧 Worker 继续处理新契约任务。
