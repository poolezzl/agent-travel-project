|---|---|---|---|

## 关键设计

- **ALG-04（POI 消歧）**：名字仅用于消歧，绝不作为主键；坐标/城市/坐标系一律取自 POI 端口，不信任候选输入；同名不自动合并。产出：缺上下文→澄清、无匹配→`SOURCE_UNAVAILABLE`、多匹配→带候选澄清、跨城→`CROSS_CITY`、缺坐标→`MISSING_COORDINATE`、非 GCJ02→`COORDINATE_SYSTEM_MISMATCH`。
- **ALG-05（确定性贪心 + 2-opt）**：O(n²) 距离矩阵只来自地图/路线端口（无 LLM）；每次 2-opt 交换必须同时降低总成本且保持可行；固定起终点不动；算法版本与 seed 集中在 `config.py`；tie-break 按索引升序，输出字节级一致；`total commute == sum(segment.duration_min)` 以断言强制；通勤/游玩/排队/用餐时间分离。
- **ALG-06（三级降级）**：固定顺序「新鲜精确缓存 → 直线估算（`is_estimated=true`）→ 不可用」；估算仅展示、不通过硬可行性 Gate；AUTH/QUOTA 不写负缓存；超时/跨城/不可达→结构化冲突；无解→`failed`。
- 退化输出遵守 envelope：`degraded` 必带 `degraded_fields` + `message`；`failed` 必带 `error_code` + `message`。

## 真实适配器设计（Step 1）

- **只新增、不改 Protocol**：`ports.py` 的 `PoiPort.lookup/get`、`RoutePort.route`、`RouteCache.get/put` 原样保留，适配器反向实现它们。
- **`amap_poi_adapter.py`**：`poi_id`/`name`/`city_id`/经纬度/坐标系全部取自高德权威字段（`id`/`name`/`adcode`/`location`），坐标绝不按名称猜测；`location` 缺失或经纬度越界（|lng|>180 或 |lat|>90）的记录直接丢弃，不作近似；同名多条原样返回，交由 ALG-04 判定歧义，不自动合并。
- **`amap_route_adapter.py`**：`RouteQuery` 只有 poi_id，适配器经注入的 `PoiPort.get` 回查权威坐标后组请求；成功返回时 `source_record_id` 由 `(坐标系, 城市, 起点, 终点, 方式)` SHA-256 生成、`retrieved_at` 取服务端时间、`is_estimated=false`。**未支持的方式（公交/地铁/混合）返回 `DIRTY` 且不发请求**（S10 后端同样只实现 driving/walking）。
- **`redis_route_cache.py`**：只存 `RouteData`，TTL 由 `RouteAdapterSettings.route_cache_ttl_seconds` 注入到 `setex`；缓存键前缀承载供应商版本。过期条目由后端存储直接淘汰，绝不回放为新鲜事实；反序列化失败按未命中处理。
- **负缓存**：`RouteProvider` 仅在得到精确 `RouteData` 时 `put`，AUTH/QUOTA 天然不写负缓存，无需额外分支。
- **`wiring.py`**：`build_route_deps(store=None, client=None)` 读取 `ROUTE_PROVIDER`/`ROUTE_CACHE_ENABLED`/`ROUTE_CACHE_TTL_SECONDS`；`store`/`client` 仅用于测试注入。`mock` 分支返回占位替身（真实种子由测试直接注入）。ALG-06 `RouteProvider` 与入口 `plan_route(request, poi_port, route_provider)` **均未改动**。

### 高德响应 → `RouteErrorKind` 映射表（记录用）

| 高德触发 | `RouteErrorKind` | ALG-06 处理 |
|---|---|---|
| HTTP 401/403；infocode `10001` `10005` `10006` `10007` | `AUTH` | 不可用，不写负缓存 |
| infocode `10003` `10044` | `QUOTA` | 不可用，不写负缓存 |
| HTTP 429；infocode `10004` `10021` `10029` `10041` | `RATE_LIMITED` | 直线估算（有坐标时） |
| HTTP ≥500；`httpx.HTTPError` 网络异常 | `UNREACHABLE` | 不可用 |
| 2xx 但 `status != "1"`；其他非 2xx；JSON 解析失败 | `DIRTY` | 直线估算（有坐标时） |
| `paths` 为空；`distance`/`duration` 缺失 | `EMPTY` | 直线估算（有坐标时） |
| 端点无权威坐标；不支持的交通方式 | `DIRTY` | 直线估算 / 不可用 |

`httpx.TimeoutException` → `TIMEOUT`（ALG-06 中与 AUTH/QUOTA 同级，直接不可用，不做估算）。

## S11 挂载（Step 3）

- S11 调用点为 `MockAgentExecutor.execute(taskId, stepName="route", attemptNo)`（`TaskWorkDefinitions`：ROUTING→`route`），返回 `WorkerResult(resultId, status, result, degradedFields)`；`TaskWorkerClaimService.commit()` 以 `(task_id, step_id, attempt_no)` 唯一键 + canonical JSON hash 落库，重复即复用既有 `resultId`。
- Python 侧对应物为 `worker.py::run_route_step(task_id, attempt_no, day_requests, poi_port, route_provider)`：**逐日**调用 `plan_route`，再聚合成一个步骤载荷。
- **envelope 字段不由 `plan_route` 注入**：`schema_version`/`task_id`/`trace_id`/`request_id`/`generated_at` 由 S11 或 LLM 网关注入；本层仅投影 `source_metadata`。
- `source_metadata` 投影：精确段 → `source_type="map"`、`freshness_status="fresh"`、`valid_until=null`；估算段 → `source_type="system"`、`freshness_status="unknown"`、`is_estimated=true`。按 `(source_type, source_record_id)` 去重。
- 聚合：全部成功→`ok`；存在失败且存在成功→`partial`（`degraded_fields` 含 `day:<日期>`）；全部失败→`failed`（带 `error_code`+`message`）；存在降级无失败→`degraded`（`degraded_fields` 含 `route.segments`）。
- **幂等**：同一 `(task_id, day, attempt_no)` 且依赖状态相同（ALG-14 缓存未过期）时输出字节级一致——缓存命中保留首次 `retrieved_at`；`fingerprint` 暴露 canonical hash 供 S11 校验。估算段 `route.is_estimated=true`，不通过 ALG-05 硬可行性 Gate。
