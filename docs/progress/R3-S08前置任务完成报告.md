## 接口表

| 接口 | 调用方向 | 输入 | 输出 | 当前状态 |
|---|---|---|---|---|
| source_registry | R3/R7 → 数据层 | 来源、许可、取得时间、有效期、审核信息 | source_record_id、freshness_status、content_hash | S06 数据规范已完成 |
| poi_import | R3/R7 → 数据层 | POI ID、城市、名称、别名、坐标、类别、来源 | POI 草稿或错误清单 | 模板已完成，S04/S15 实现 |
| attraction_import | R3/R7 → 数据层 | knowledge_id、poi_id、事实类型、chunk、来源 | 景点知识草稿 | 模板已完成，S04/S15 实现 |
| reservation_rule_import | R3/R7 → 数据层 | policy_id、票种、渠道、时区、价格、生效期、核验时间 | 预约规则草稿 | 模板已完成，S04/S17 实现 |
| attractions Agent | 总控 → R3 Agent | points、preference_tags | cards、知识引用和来源元数据 | Schema 已冻结，S16 实现 |
| dining/lodging Agent | 总控 → R3 Agent | date、itinerary_draft、偏好、预算、同行人 | meals、lodging、POI、价格、detour_min | Schema 已冻结，S18 实现 |
| reservation rules Agent | 总控 → R3 Agent | points、date | reservations、timeline、stale、来源元数据 | Schema 已冻结，S17 实现 |
| agent-results | Python Agent → Java 网关 | 统一封套、result、Idempotency-Key | 202 accepted 或 409 duplicate | OpenAPI 已冻结，运行时由后续步骤接入 |

接口的详细字段和责任方见 docs/data/r3-interface-table.md。R3 提交事实和 Agent 结果，R5 负责 Java 业务写入与权限，R1 负责调度整合，R2 提供路线绕行结果，R7 负责质量验收。
