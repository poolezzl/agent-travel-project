#### 1.1 `-DforkCount=0` 带来的连带约束（本次新发现）

`-DforkCount=0` 会让测试在 Maven 进程内执行，`user.dir` 变为**调用 Maven 的目录**，而不是 `${basedir}`。`backend/src/test/java/com/agenttravel/backend/task/S11ContractTests.java:20` 用 `Path.of("..").toAbsolutePath()` 定位 `contracts/`，因此 Maven 必须在 `backend/` 目录内执行：

- 在仓库根执行 `mvn -B -o -DforkCount=0 -f backend/pom.xml test`：5 个 error，`NoSuchFile D:\contracts\openapi\s11-tasks.yaml`、`FileNotFound D:\contracts\examples\s11\create-task-request.json`，`Tests run: 252, Failures: 0, Errors: 5, Skipped: 53`，`BUILD FAILURE`。
- 在 `backend/` 内执行 `mvn -B -o -DforkCount=0 test`：`Tests run: 252, Failures: 0, Errors: 0, Skipped: 53`，`BUILD SUCCESS`。

据此，`.github/workflows/s03-cross-stack.yml` 的 `backend` job 增加 `defaults.run.working-directory: backend`（MySQL 校验步骤单独用 `working-directory: .` 保持在仓库根），与 `backend.yml` 的既有写法一致。

#### 1.2 pytest 临时目录

`agent-service-ci.yml` 的质量门禁步骤与 `s03-cross-stack.yml` 的 Python 测试步骤统一注入：

```yaml
env:
  TMPDIR: ${{ runner.temp }}/agent-service-tmp
  TMP: ${{ runner.temp }}/agent-service-tmp
  TEMP: ${{ runner.temp }}/agent-service-tmp
```

并在运行前 `mkdir -p "$TMPDIR"`；`pytest` 追加 `--basetemp="$TMPDIR/pytest-basetemp"`，使 pytest 的临时目录完全落在 runner 自有工作目录内，不再依赖宿主默认临时目录的权限模型。

#### 1.3 换行基线

新增 `.gitattributes`：`* text=auto eol=lf`，`*.bat`/`*.cmd`/`*.ps1` 为 `text eol=crlf`，常见二进制扩展名标记 `binary`。复核 `git ls-files --eol`：746 个跟踪文件中只有 8 个 `scripts/*.ps1` 为 `w/crlf`（属性声明 `eol=crlf`），其余全部 `i/lf w/lf`；索引 blob 无变化（`git diff --cached --stat` 只包含本次新增/修改文件），因此不存在换行造成的全仓 diff。

#### 3.4 s03-cross-stack 的 OWASP 依赖扫描：免密钥方案与实测代价

- run 45597610697：5 个 job 全部 success。步骤级：Frontend lint/unit test/build ✓(36s)、Schema and OpenAPI validation ✓、Secret and dependency manifest scan ✓、Agent service checks ✓(40s)、Java build/tests/Flyway check ✓（Verify backend 19s、Cache NVD database、Dependency vulnerability scan 29min15s、Verify isolated MySQL 8 and Redis 56s）。
- 该步骤最初的红是 `dependency-check 13.0.0` 强制要求 NVD API Key（`Invalid API Key, length of 0 too short`）。最终方案**不需要任何密钥**：
  - 改用 `dependency-check-maven:12.2.2`，匿名访问 NVD 仍可用（实测 `GET https://services.nvd.nist.gov/rest/json/cves/2.0?resultsPerPage=1` 返回 200，共 432078 条 CVE）；
  - 匿名限速为 5 次/30 秒，默认速率会触发 429（实测重试 18 次后仍失败，耗时 23 分钟），因此显式压低速率：`-Dnvd.api.delay=8000 -Dnvd.api.requestsperthirtyseconds=4`；
  - 用 `actions/cache` 缓存 `~/.m2/repository/org/owasp/dependency-check-data`，后续 run 走增量更新；
  - 若仓库配置了 Secret `NVD_API_KEY` 则自动改用密钥（限速 50 次/30 秒），无需改 workflow；
  - `failBuildOnCVSS=11` 保持原语义：只出报告，不改构建结论。
- **代价与收益（如实记录）**：首次运行需同步整个 NVD 库，约 29 分钟（run 45597610697：依赖扫描 11:22:22 前的 29 分 15 秒）；缓存命中后同一扫描仅 **13 秒**（run 45603709537：`Dependency vulnerability scan` 11:22:22 → 11:22:35，整个 workflow 1 分 43 秒）。该步骤是首次运行耗时的主因，后续 run 不再是瓶颈。
- run 45603709537（commit `24a03c5`）为缓存生效后的第二次绿色 run：5 个 job 全部 success（Frontend 26s、Schema 9s、Secret 7s、Agent service 36s、Java 99s）。
