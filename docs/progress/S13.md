## 关键设计

- **ALG-07 窗口判定**：`today` 由系统注入；`days_ahead = date - today`；`0 ≤ days_ahead < forecast_horizon_days` → `forecast`，`≥ forecast_horizon_days` → `climate_statistics`（标注「非预报数据」）；同一输出可混合两类。过去日期（`< today`）与倒置区间 → `INVALID_INPUT`。
- **气候统计分流**：窗口外只能气候统计；`precip_prob` 无可靠概率时 `null`（`make_climate` 默认 `None`）。
- **供应商时区**：日期按供应商时区计算，时区由适配器注入、绝不写死；`local_date` 用 `ZoneInfo` 处理夏令边界。
- **ALG-14 缓存**：缓存键 `weather:v1:{city_id}:{day}:{data_type}:{timezone}`（格式 PENDING）；AUTH/QUOTA 不写负缓存；**过期预报绝不回放**（当日失败）；过期气候统计可回放并标注 `stale`。
- **降级聚合**：部分日期失败 → `partial`（`degraded_fields=["daily"]`）；全部失败 → `failed`（全超时 `AGENT_TIMEOUT`，否则 `SOURCE_UNAVAILABLE`，`message="天气服务暂不可用"`、`daily` 空，不默认晴天）；有 stale 气候且无失败日 → `degraded`。
- **脏数据防护**：端口返回 `data_type` 不符、`temp_min > temp_max`、`precip_prob` 越界（[0,1]）的日期按脏数据处理为失败，不崩溃。

## 测试覆盖

- 窗口边界（today / horizon-1 / horizon）、跨月/跨年 `days_ahead` 与 `enumerate_dates`、过去日期拒绝。
- 时区/DST：纽约春令（2026-03-08 07:00 UTC）与秋令（2026-11-01 06:00 UTC）边界、UTC 日期跨日（时区确实生效）。
- 缓存：新鲜命中短路端口、过期预报回源、过期气候标注 stale、过期预报绝不回放、AUTH/QUOTA 不写负缓存、成功写缓存。
- 编排：混合预报/气候统计输出（气候 `precip_prob=null`）、倒置区间与早于 today → `INVALID_INPUT`、极端高温风险 + 敏感点不可行、强降水风险、单日失败 → `partial`、全超时 → `AGENT_TIMEOUT`、全不可达 → `SOURCE_UNAVAILABLE`（不默认晴天）、`temp_min>temp_max` 脏数据 → 当日失败、stale 气候 → `degraded`、穿衣建议仅在 `ask_clothing` 时给出、同输入两次字节级一致。

## 边界场景

- 成功：混合预报/气候统计、同输入字节级一致、敏感点可行/不可行。
- 空值/非法：倒置区间、早于 today、`temp_min>temp_max`、`precip_prob` 越界、`data_type` 不符。
- 失败：单日失败（partial）、全超时（AGENT_TIMEOUT）、全不可达（SOURCE_UNAVAILABLE，不默认晴天）。
- 降级：stale 气候回放 → `degraded`；过期预报不回放。
- 时区：DST 春令/秋令边界、UTC 日期跨日。

## 来源 / 权限 / 幂等 / 并发 / 降级 / 隐私 / 日志 / 回滚检查
