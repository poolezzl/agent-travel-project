| 能力 | S10 Java 真实接口 | dev-r2 Python Protocol | 差异与处理 |

| 逐日字段 | `date, tempMin, tempMax, precipProbability, condition, dataType, sourceRecordId, retrievedAt, validUntil, freshnessStatus` | `DailyWeather` 同名字段 + `city_id` | 基本 1:1；Python 额外要求 `city_id` |

## 关键设计

- **ALG-07 窗口判定**：`today` 由系统注入；`days_ahead = date - today`；`0 ≤ days_ahead < forecast_horizon_days` → `forecast`，`≥ forecast_horizon_days` → `climate_statistics`（标注「非预报数据」）；同一输出可混合两类。过去日期（`< today`）与倒置区间 → `INVALID_INPUT`。
- **气候统计分流**：窗口外只能气候统计；`precip_prob` 无可靠概率时 `null`（`make_climate` 默认 `None`）。
- **供应商时区**：日期按供应商时区计算，时区由适配器注入、绝不写死；`local_date` 用 `ZoneInfo` 处理夏令边界。
- **ALG-14 缓存**：缓存键 `{supplier}:weather:v1:{city_id}:{day}:{data_type}:{timezone}`（`weather_key` 格式 PENDING，供应商段由适配器注入）；AUTH/QUOTA 不写负缓存；**过期预报绝不回放**（当日失败）；过期气候统计可回放并标注 `stale`。
- **降级聚合**：部分日期失败 → `partial`（`degraded_fields=["daily"]`）；全部失败 → `failed`（全超时 `AGENT_TIMEOUT`，否则 `SOURCE_UNAVAILABLE`，`message="天气服务暂不可用"`、`daily` 空，不默认晴天）；有 stale 气候且无失败日 → `degraded`。
- **脏数据防护**：端口返回 `data_type` 不符、`temp_min > temp_max`、`precip_prob` 越界（[0,1]）的日期按脏数据处理为失败，不崩溃。

## 真实适配器设计（Step 1）

- **只新增、不改 Protocol**：`WeatherPort.forecast/city`、`WeatherCache.get/put` 原样保留，适配器反向实现。
- **`qweather_adapter.py`**：
  - `forecast` 请求 `/v7/weather/{N}d`，`N` = 配置的真实预报档位（默认 **3**，与 S10 `QWEATHER_FORECAST_DAYS=3` 一致），通过 `forecast_horizon_days` 属性暴露；在 `daily[]` 中按 `fxDate` 取当日，无记录→`EMPTY`。
  - `climate` 请求 `/v7/historical/weather?date=YYYYMMDD`，结果标 `data_type=climate_statistics`、`precip_prob=null`（历史观测无概率，**不编造**）。
  - 日期按注入的 `ZoneInfo` 计算当日结束（DST 感知），**适配器不决定 "today"**，也不写死任何时区。
  - `temp_min > temp_max`、`precip_prob` 越界、日期与请求不符、字段缺失→`DIRTY`。
- **`redis_weather_cache.py`**：
  - 键由 `weather_provider.weather_key` 生成：`weather:v1:{city_id}:{day}:{data_type}:{timezone}`。
  - ALG-14 要求键内含供应商版本，而 `weather_key` 不承载该段（格式 PENDING-R5），因此适配器以 `key_prefix`（`QWEATHER_PROVIDER_ALIAS`，默认 `qweather`）做命名空间，完整键为 `qweather:weather:v1:...`；更换供应商不会误复用旧缓存。
  - TTL 来自配置（`WEATHER_CACHE_TTL_SECONDS`，默认 **3600s**，与 S10 `weatherCacheTtlSeconds` 一致）。
  - 预报条目在 `valid_until` 到期即失效，`get` 亦拒绝已过期预报——**过期预报绝不回放**。
  - 气候条目保留期更长（`WEATHER_CLIMATE_RETENTION_SECONDS`，默认 **30 天**），超过新鲜度后仍可被 ALG-07 回放并标 `stale`。
  - **AUTH/QUOTA 不写负缓存**：缓存只存成功取得的 `DailyWeather`，无负缓存入口。

### 和风天气响应 → `WeatherErrorKind` 映射表（记录用）

| 和风触发 | `WeatherErrorKind` | ALG-07 处理 |
|---|---|---|
| HTTP 401/403；`code` 401/403 | `AUTH` | 当日失败，不写负缓存 |
| `code` 402 | `QUOTA` | 当日失败，不写负缓存 |
| HTTP 429；`code` 429 | `RATE_LIMITED` | 当日失败（气候可回放 stale） |
| HTTP ≥500；网络异常 | `UNREACHABLE` | 同上 |
| `code` 204；`daily` 为空；无当日记录 | `EMPTY` | 同上 |
| JSON 解析失败；`code` 400/404；温度倒置；`pop` 越界；字段缺失；城市未配置 | `DIRTY` | 同上 |
| `httpx.TimeoutException` | `TIMEOUT` | 当日失败；全部超时→`AGENT_TIMEOUT` |

## S11 挂载（Step 3）

- S11 `TaskWorkDefinitions`：`COLLECTING` → stepName `collect`；`TaskWorkerClaimService.commit()` 以 `(task_id, step_id, attempt_no)` 唯一键 + canonical JSON hash 落库。
- Python 对应物 `worker.py::run_weather_step(task_id, attempt_no, requests, provider, port)`：对每个请求调用 `run_weather`（多请求用线程池并行，`map` 保持输入顺序以保证确定性）。
- **`forecast_horizon_days` 取自真实适配器**（`port.forecast_horizon_days`），覆盖请求中的值；`today` 仍由调用方注入，适配器不参与。
- **envelope 字段不由 `run_weather` 注入**：`schema_version`/`task_id`/`trace_id`/`request_id`/`generated_at` 由 S11 / 网关注入；本层只投影 `source_metadata`。
- `source_metadata` 投影：`source_type="weather"`、`source_record_id`、`retrieved_at`、`valid_until`、`freshness_status`（按 `valid_until` 与当前时刻判定 fresh/stale，无有效期则 unknown）、`is_estimated=false`。
- 聚合：全部失败→`failed` + `message="天气服务暂不可用"` + `daily=[]`；存在失败→`partial`；存在过期→`degraded`；否则 `ok`。
- **幂等**：同一 `(task_id, attempt_no)` 且缓存状态相同→字节级一致；`fingerprint` 暴露 canonical hash 供 S11 校验。

## 边界场景

- 成功：混合预报/气候统计、同输入字节级一致、敏感点可行/不可行。
- 空值/非法：倒置区间、早于 today、`temp_min>temp_max`、`precip_prob` 越界、`data_type` 不符。
- 失败：单日失败（partial）、全超时（AGENT_TIMEOUT）、全不可达（SOURCE_UNAVAILABLE，不默认晴天）。
- 降级：stale 气候回放 → `degraded`；过期预报不回放。
- 时区：DST 春令/秋令边界、UTC 日期跨日。

## 来源 / 权限 / 幂等 / 并发 / 降级 / 隐私 / 日志 / 回滚检查

- 隐私/日志：不记录原始 Prompt、凭证或完整私密行程；输出仅含必要的日期/气温/降水/来源字段。适配层不打印和风 Key、请求 URL 或原始响应体，错误 `message` 只含稳定描述。
